## Reviewer instructions

Give an independent reviewer only the three files in `retrieval_review_v1/`.
Keep previous pair labels, pilot reports and rankings hidden. Source titles,
URLs and publication dates remain visible so the reviewer can assess relevance
and temporal suitability. This workflow records an independence attestation;
it does not authenticate a person's identity or prove they remained blinded.

In `judgments.json`, the reviewer:

1. Enters `reviewer`, `reviewed_on` (ISO date), and confirms
   `independent_review` and `blinded_to_results` only when true.
2. Sets each query's `suitable` to `true` or `false`, with concerns in `notes`.
3. Sets every candidate's `relevant` to `true` or `false`. A relevant candidate
   requires a nonempty `evidence_span` copied verbatim from that passage. An
   irrelevant candidate retains `evidence_span: null`.

A rejected query needs curation and a fresh packet; the exporter will not
silently drop it. Each accepted query needs at least one reviewed positive.
These are retrieval relevance labels, not causal-edge direction, strength,
provenance, or anchor-episode annotations owned by Track B.

## Export completed review

Run from the repository root, selecting an unused output directory:

```sh
PYTHONPATH=src .venv/bin/python -m retrieval.review export \
  --packet data/interim/retrieval_review_v1/packet.json \
  --judgments data/interim/retrieval_review_v1/judgments.json \
  --corpus data/processed/articles.jsonl \
  --output data/interim/retrieval_review_accepted_v1
```

This creates `pairs.jsonl` and `receipt.json` only after validating the whole
review. Incomplete judgments, absent or duplicated items, a reviewer matching
the curator, missing attestations, nonverbatim spans, changed packet/corpus,
and post-cutoff candidates fail before output creation. Existing output
directories are preserved. Retain the completed judgments locally: the receipt
records their hash but does not reproduce their text.

A non-smoke `retrieval.pilot_runner` run now requires
`--review-receipt data/interim/retrieval_review_accepted_v1/receipt.json` and
`--pairs data/interim/retrieval_review_accepted_v1/pairs.jsonl`. The runner checks
their hashes, query identities and positive counts before constructing models.
The research pilot still requires exactly 20 queries. Use `--smoke` for
development without a completed review. Neither mode edits the shared decision
log or resolves D-02/D-03 automatically.

## Recreate or expand a packet

For a new query set, run the existing four-configuration smoke command with
`--candidate-output <fresh-local-pool.jsonl>` and a fresh development report.
Candidate output contains `query_id`, `query`, `as_of` and **`passage_ids`**.
It intentionally does not use the positive-label field. Reranking does not add
passages beyond the same first-stage top 50.

Then prepare a packet in another unused directory:

```sh
PYTHONPATH=src .venv/bin/python -m retrieval.review prepare \
  --pairs reports/retriever_pilot_pairs.jsonl \
  --corpus data/processed/articles.jsonl \
  --aliases data/aliases.yaml --curator 'Varun Patil' \
  --candidate-pool data/interim/retrieval_review_candidates_v1.jsonl \
  --output data/interim/retrieval_review_v2
```

Without `--candidate-pool`, preparation uses seed candidates plus plain/alias
BM25 top 10. It explicitly flags omitted dense-only candidates; this smaller
packet is a preparation aid, not an exhaustive comparison pool.
