## Reported defects and portability

- Claude completions now satisfy the shared run-log schema. Offline integration checks use the real native adapter and logger with mocked API responses.
- A strength-only update cannot turn an approved conditional assertion into a direct one. Replacing evidence, omitting provenance, stale approvals and failed reverification are covered.
- `verify_edge` accepts source-asserted success only with supported verdict, direction, strength, approved edge and exact source/span evidence, with no rule failures.
- The retrieval worker uses a reader thread/queue for subprocess pipes. Native Windows tests cover consecutive requests, timeout cleanup and restart after child failure, without the socket-selector failure.
- Receipts use portable paths and UTF-8/LF bytes; source identity normalizes CRLF. Legacy Windows receipt separators normalize without weakening duplicate, traversal or tamper checks. Changed inputs or source intentionally require a new run directory.
- Evaluation reads use UTF-8, portable path/error-message checks pass, and Windows timezone data is installed. MLX gives an actionable message on Windows/Linux; those systems use explicit llama.cpp/vLLM endpoints.

## Scope of completion

The 25-response safety review is explicitly by Codex as an assistant. It records all four outcomes and reasons and does not claim independent human certification. The action/model/safety cases are synthetic. Baseline/ablation quotation errors remain visible in the Kaggle audit; they are evaluation outcomes and are not silently rewritten. Run `make validate-track-c` to reproduce the fail-closed evidence gate. Missing or changed evidence fails the command. Passing tests describes these checked executions, not a guarantee against every future error.
